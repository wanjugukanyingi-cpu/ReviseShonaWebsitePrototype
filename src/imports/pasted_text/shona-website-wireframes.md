Create the revised Shona website + product wireframe/prototype in Figma, using the attached/current Shona web sketch and Shona logo as the source material. Do not create a written description only. Build the actual visual, page-by-page wireframes, arranged chronologically so the entire Shona experience can be understood from first website arrival through both the brand and customer journeys.
CORE CONCEPT
Shona is after-sales infrastructure for clothing brands.
It helps clothing brands:
•	recover value from damaged inventory;
•	give customers a trusted way to repair or alter garments they purchased;
•	coordinate intake, specialist assessment, logistics and communication;
•	generate operational/product intelligence from after-sales activity.
Use the existing Shona terminology and concept. Use the supplied Shona logo as the visual anchor.
Visual direction: modern, intelligent, warm and practical. Use the Shona orange as an accent, warm ivory/off-white for public pages, white for dense portal screens, and charcoal typography. Avoid generic “green sustainability” aesthetics.
IMPORTANT PRODUCT DISTINCTION
Keep these two systems completely separate:
BRAND PORTAL = inventory recovery + operational/product intelligence.
CUSTOMER EXPERIENCE = booking + logistics + repair/alteration status + communication.
Brand inventory tracking must NEVER be presented as customer garment tracking.

Build these frames in exactly this order:

03. How Shona Works — Two After-Sales Experiences
Explain the system visually as ONE after-sales system with TWO experiences.
Experience 1 — Brand / Acquisition / Inventory:
Manufacturing → Product Design → Damage/Quality Issue → Shona Assessment → Repair/Alteration → Recover Value → Return to Brand Ecosystem.
Experience 2 — Customer Aftercare:
Brand sells → Customer buys → Customer needs repair/alteration → Shona coordinates intake + specialist + logistics → Garment repaired/altered → Customer remains in brand ecosystem → Brand learns from patterns.
Show that this can create an additional revenue opportunity for the brand and generate product insights.
04. For Brands

Position Shona as infrastructure rather than simply a repair marketplace.

11. Customer Booking — Assessment + Predictable Pricing
Step 2.
Customer selects/describes issue:

21. Research-Informed Design Decisions
Create a final annotation frame explaining the key UX decisions incorporated:
•	progressive disclosure to reduce decision fatigue;
•	predictable pricing to reduce uncertainty;
•	structured intake before human/WhatsApp interaction;
•	calendar-based scheduling;
•	address form first, map second;
•	separate customer tracking from brand inventory tracking;
•	human specialist escalation where diagnosis/pricing is uncertain;
•	readable catalogue/table design;
•	operational data captured throughout the journey;
•	WhatsApp used as a communication layer rather than the core system.
Clearly label these as research-informed design decisions, separate from the original Shona source material.
